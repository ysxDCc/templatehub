# TemplateHub redesign — design spec

**Date:** 12 November 2026
**Status:** Awaiting approval
**Owner:** Leo (ysxDCc)

## 1. Goal

Rebuild TemplateHub's front end so it looks cleaner, feels more alive, and is easy to use on a phone — without changing what the site does.

**Success looks like**

- A visitor on a phone can browse templates, try the Studio and reach checkout with one thumb, without zooming or sideways scrolling.
- The site keeps its dark purple identity but reads as calm and premium, not cluttered.
- Motion makes the site feel responsive, never slow; people who turn on "reduce motion" get a still version.
- Nothing that works today breaks: accounts, checkout, webhooks, downloads, template protection, forms, AI Studio, SEO.

**Out of scope**

- Back-end behaviour, pricing, plan rules, page URLs, SEO metadata, the template files themselves.
- New features beyond what is listed here.

## 2. Decisions already made

| Topic | Decision |
|---|---|
| Visual direction | Keep the dark purple brand, make it cleaner |
| Approach | Staged rebuild on a shared design system; each stage ships separately |
| Animation tech | CSS transitions/keyframes + a small IntersectionObserver hook; no animation library |
| Extra preview tools (Sniper, X-Ray, Heatmap, Race, 3D frame, Remix, vision filters, QR, Social Card, CSS tokens, Brand cloner) | Kept, moved into a "More tools" menu |

## 3. Design system

### 3.1 Tokens (single source in `src/app/globals.css` via Tailwind v4 `@theme`)

- **Colour:** background `#08051A` (near-black purple), surface `#110A2B`, raised surface `#1A1140`, border `rgb(168 85 247 / 0.18)`, primary `#7C3AED` (white text on it = 5.7:1), primary-hover `#6D28D9`, accent lilac `#C4B5FD` (used for links and highlights, 10.9:1), text `#F5F3FF` (18.3:1), muted text `#B9AED9` (9.7:1), success `#34D399`. Purple `#8B5CF6` is decorative only, never for text.
- **Glow:** at most one soft radial glow per page section; remove scanlines, particle canvas, aurora layers and per-element neon shadows.
- **Type:** Inter. Scale: 14 / 16 / 18 / 22 / 28 / 36 / 48 / 64 px. Body text never below 16px on phones; form inputs 16px (prevents iOS zoom). Monospace only for code.
- **Radius:** 10px (controls), 16px (cards), 24px (sections/sheets).
- **Spacing:** 4px base; section padding 64px phone / 112px desktop.

### 3.2 Motion

- Durations 150–400ms, easing `cubic-bezier(.2,.8,.2,1)`.
- **Reveal:** sections and cards fade + rise 12px when 15% visible; children stagger 60ms.
- **Cards:** lift 4px and brighten border on hover/focus; scale 0.98 on press.
- **Buttons:** press scale 0.97; primary button has a subtle shine on hover (desktop only).
- **Page transitions:** 200ms fade on route change.
- **Hero preview:** cross-fades between templates every 5s; pauses on hover/focus and when off-screen.
- **`prefers-reduced-motion: reduce`:** all of the above disabled; content shows immediately; carousel does not auto-advance.
- Sound effects default off; the toggle moves into the menu.

### 3.3 UI components (`src/components/ui/`, one per file)

| Component | Purpose |
|---|---|
| `Button` | primary / secondary / ghost; sizes sm/md/lg; min height 44px; works as link or button |
| `Card` | surface container with optional interactive (lift) state |
| `Chip` | filter chip, toggle state via `aria-pressed` |
| `ChipScroller` | horizontally swipeable chip row with edge fade |
| `Section` | consistent section padding, heading + subheading slot |
| `Reveal` | scroll-in animation wrapper (IntersectionObserver, reduced-motion aware) |
| `BottomSheet` | phone popup sliding from bottom; focus trap, Esc/swipe-down to close; becomes centred dialog on desktop |
| `Accordion` | FAQ / disclosure using native `<details>` styling |
| `Tabs` | accessible tablist (arrow-key navigation) |
| `Badge` | tier/status label |

### 3.4 Navigation

- **Top bar:** logo, desktop links (Templates, Studio, AI Studio, Pricing, Licensing), search (⌘K), Affiliate, account. Phone: logo + search + account only.
- **Phone bottom tab bar** (below 768px): Home, Templates, Studio, Pricing, Account. 56px tall plus safe-area inset; active tab marked with `aria-current="page"`.
- Replaces `Navbar.tsx`; existing Command Palette and Referral modal are reused.

## 4. Pages

### Stage 1 — Navigation + homepage
1. **Hero:** headline, one-line subhead, primary "Browse templates", secondary "Try the Studio free". Live preview rotating 4–5 templates (iframes of `/preview/[id]`, lazy, one loaded at a time).
2. **How it works:** 3 steps with small animated icons.
3. **Templates by industry:** `ChipScroller` + card grid (1 col phone, 2 tablet, 4 desktop), 8 cards, "See all" link.
4. **Studio demo:** looping CSS animation of a template being edited (no video file).
5. **Why TemplateHub:** one strip combining no-dependencies, brand colours and speed points.
6. **Pricing:** 4 plans; phone = horizontal swipe cards starting on Pro.
7. **FAQ:** `Accordion`, 5–6 questions (existing answers + trial/refund/licence).
8. **Final CTA.**

### Stage 2 — Templates list
- Sticky search; desktop sidebar filters, phone "Filters" button opening a `BottomSheet`.
- Larger cards; tap opens template page; separate "Quick look" opens preview sheet.

### Stage 3 — Template page
- Preview first; info + plan/download panel beside it on desktop, below it on phone.
- Phone: sticky bottom bar with price/plan and primary action.
- Preview toolbar: Preview / Auto-Edit / Code tabs + device switcher; all other tools in a "More tools" menu.
- `InteractivePreviewFrame.tsx` (≈1,500 lines) split into: `PreviewToolbar`, `DeviceFrame`, `AutoEditPanel`, `CodePanel`, `ToolsMenu`, plus a `usePreviewSource` hook. Behaviour unchanged.

### Stage 4 — Studio
- Desktop keeps three columns. Phone: tabs "Template / Edit / Preview" with sticky "Apply" + "Download" bar.

### Stage 5 — Everything else
- Pricing details, Compare, AI Studio, Builder, legal/info pages, login/signup, checkout pages, admin: new tokens and components, same layouts.

## 5. Unchanged contracts

- All API routes, middleware, Clerk/Dodo/Resend integration, template protection.
- Every page URL, `generateMetadata`, sitemap, robots, JSON-LD.
- Data files (`templates.ts`, `pricing.ts`, `reviews.ts`) — read-only for the redesign.

## 6. Accessibility requirements

- WCAG 2.2 AA contrast for all text; visible focus ring (2px lilac) on every interactive element.
- Tap targets ≥ 44×44px.
- Icon-only buttons have `aria-label`; no information conveyed by colour alone.
- Dialogs/sheets trap focus and restore it on close; Esc closes.
- Skip-to-content link kept; landmarks (`header`, `nav`, `main`, `footer`) correct.
- No horizontal page scroll at 320px width.

## 7. Performance requirements

- Homepage first-load JS no larger than today (195 kB); remove `CosmicPurpleCanvas` from the homepage.
- Hero preview iframes load lazily, one at a time.
- No new runtime dependencies.

## 8. Testing (every stage)

1. `next build` passes (type check + lint).
2. Screenshots at 390px and 1440px of every changed page, reviewed.
3. Automated checks: no horizontal overflow at 320/390px; tap targets ≥ 44px; axe-core scan with no serious/critical issues.
4. Studio flow: edit → apply → preview → download prompt.
5. `prefers-reduced-motion` screenshot shows content without animation.

## 9. Rollout

- One branch per stage: `redesign/1-home`, `redesign/2-templates`, `redesign/3-template-page`, `redesign/4-studio`, `redesign/5-rest`.
- Each opens a pull request; Vercel builds a preview. Screenshots + preview link sent for approval; merge after OK.
- Before stage 1: extend `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` to the Vercel Preview environment so sign-in works on preview links. The secret key is stored as a hidden value, so if Vercel won't let its target be changed, Leo re-enters it for Preview.

## 10. Risks

| Risk | Mitigation |
|---|---|
| Splitting the preview component breaks the Studio | Stage 3 keeps behaviour identical; Studio flow test runs after every stage |
| New styles leak into unredesigned pages | Old pages keep working because tokens are additive until stage 5 |
| Animation hurts phone performance | CSS-only, transform/opacity only, reduced-motion respected, JS budget enforced |
